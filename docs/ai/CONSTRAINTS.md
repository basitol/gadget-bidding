# Constraints

Hard rules. If a task seems to need breaking one, stop and ask — don't work around it.

## Never touch (files)

| Path | Why | Do instead |
| --- | --- | --- |
| `.env`, `packages/*/.env`, `packages/backend/.env.backup-render` | Real keys (some live: Termii, Paystack). | Edit `.env.example` and [ENV.md](ENV.md). Never print, copy, or commit values. |
| `packages/backend/prisma/migrations/<any applied folder>` | Prisma checksums applied migrations; editing breaks staging/production deploys. | Add a new migration. |
| `packages/backend/src/generated/**` | Generated Prisma client. | Change `schema.prisma`, run `pnpm prisma:generate`. |
| `packages/shared/dist/**` | Build output. | Edit `packages/shared/src`, rebuild. |
| `packages/mobile/ios/**`, `packages/mobile/android/**` | Generated by Expo prebuild, gitignored; hand edits vanish. | Config plugin in `packages/mobile/plugins/` or `app.json`. |
| `pnpm-lock.yaml` (by hand) | Only pnpm writes it. | `pnpm install` / `pnpm add` after approval. |
| `design/gadgets-bidding-assets/**` | Source brand pack. | Copy what a surface needs into that package. |
| `design/amber-ledger.md` | Superseded. Don't follow it. | `docs/DESIGN_GUIDE.md`. |
| Root `app.json`, root `eas.json` | Stale stubs — editing them changes nothing real and confuses. | `packages/mobile/app.json`, `packages/mobile/eas.json`. |
| Files another session is actively editing | Concurrent sessions share this checkout. | Check `git status`; if a file you didn't touch is modified, leave it. |

## Never do (actions)

- Never commit, push, or open a PR unless the user asks. Never force-push `main` or `feat/buyer-app-revamp`.
- Never run destructive DB commands (`prisma migrate reset`, `db push --force-reset`, `DROP`, `TRUNCATE`, mass `DELETE`/`UPDATE`) against anything but a throwaway local DB.
- Never fix wallet balances, holds, orders or payouts with ad-hoc SQL. Use the service functions or admin actions so the ledger and audit log stay consistent.
- Never set `SELLER_PAYOUTS_LIVE=true`, `ALLOW_PRODUCTION_RESTORE=true` or `PAYSTACK_REPLAY_ALLOW_PRODUCTION=true`.
- Never use live Paystack keys outside `APP_ENV=production`. Never text or email real people from dev (the local Termii key is live).
- Never add a dependency without approval — see [DEPENDENCIES.md](DEPENDENCIES.md).
- Never upgrade Expo SDK, React Native, Prisma, Express or React majors as a side effect of another task.
- Never invent UI tokens or components outside `docs/DESIGN_GUIDE.md` (landing page in `packages/web` follows its own pasted design).
- Never fake data in UI ("demo" numbers, placeholder sellers, fake automatic checks). Every number shown comes from the API.

## Logic that must not change without an explicit decision

Changing any of these needs the user's sign-off and an entry in [DECISIONS.md](DECISIONS.md).

### Money
- Every balance change goes through `applyBalanceDelta` (`backend/src/utils/wallet-balance.ts`) **plus** a `WalletTransaction` row, in the same transaction. The DB `CHECK (balance >= 0)` is the backstop — never remove it.
- Payment processing stays **idempotent on the reference** (`processWalletFunding`, `processOrderPayment`). Paystack retries webhooks.
- Webhook routes stay mounted with `express.raw` **before** `express.json` in `app.ts`, and signatures (`x-paystack-signature` HMAC-SHA512, `monnify-signature`) are always verified.
- The webhook checks `metadata.purpose === 'card_verification'` **before** order/wallet logic.
- Payout run: `pg_advisory_xact_lock` + `FOR UPDATE`, one batch per seller per 6 pm Lagos run, charges never split, failed payouts return orders to `ready`.
- Refund ordering in cases: claim the `DisputeReturn` status first, then call Paystack refund outside the DB transaction.
- Money is `Decimal(15,2)` naira in the DB. Kobo exists only at the Paystack boundary — always `Math.round(amount * 100)`.
- Escrow release: only buyer confirm or `autoConfirmDeliveries` after 48 h releases payout, never while a case is open or `refund_pending` is set.

### Auctions and bidding
- `placeBid` stays one interactive transaction including `assertBiddingOpen(tx)`; auto-bids go through `placeBid`.
- ₦1,000 commitment hold rules (shared `BID_COMMITMENT_AMOUNT`).
- One open (scheduled/active) auction per gadget — partial unique index `auctions_one_open_per_gadget`.
- Maintenance time give-back stays a single conditional SQL update.

### Privacy
- Buyers see sellers only as CV codes; sellers never see buyer names or addresses (`maskSellerForBuyer`, `maskBuyerForSeller`, `forViewer`).
- `gadgets.device_identifier` / `device_identifier_hash` stay in the Prisma global `omit` (`backend/src/config/prisma.ts`). Raw SQL selecting gadgets must use `stripPrivate`. Only `GET /admin/gadgets/:id` may return it.
- Seller documents stay private (Cloudinary `private` + short signed links).
- Listing reporters are visible to staff only.
- Staff names never reach buyers (hub inspection exposes `{passed,total,at}` only).

### Auth
- Staff tokens are limited to `STAFF_PATHS`; `placeBid` refuses staff.
- Password reset and account-existence responses never reveal whether an account exists.
- `TWO_FACTOR_KEY` / `JWT_SECRET`: don't rotate `JWT_SECRET` while `TWO_FACTOR_KEY` is unset (saved 2-step secrets become unreadable).
- Admin restrictions on sellers with live auctions or escrow need a second admin.

### Time
- DB timestamps are UTC wall-clock `TIMESTAMP` while the session TZ may be `Africa/Lagos`. Do date maths in SQL or cast explicitly. Lagos = fixed UTC+1; don't use `Intl` time zones on mobile (Hermes).

### Database constraints
- Status and type columns have SQL `CHECK` constraints (e.g. `gadgets_status_check`, `verification_type`, `payment_transactions.status`). Don't write a new value without a migration that allows it.
- `orders_record_event` trigger is the source of truth for order stage times — don't duplicate it in app code.

## Mobile-specific
- No new native modules without approval; any native module must be lazy-required (see DECISIONS.md › Mobile).
- Keep the app working on older dev builds: feature-detect, don't assume.
- Inside `GlassScreen`, use `GlassKeyboardView`.
- UI copy rules in `AGENTS.md`: no raw enums, no exclamation marks in titles, no emoji, no marketing filler.
